# Initial pinned toolchain

The root flake pins Nixpkgs and rust-overlay revisions. Rust is selected from the existing `rust-toolchain.toml` (1.98.1); the declared minimum is now Rust 1.88, raised from 1.85 because rcgen 0.14.10 requires it. The development compiler and tested minimum are separate contracts. Bun 1.4.2 uses a custom release derivation because the selected Nixpkgs revision need not carry the required version. Its ARM64 glibc archive is pinned to the GitHub release SHA-256 (`54328bbc2d9c8e0c9f892c544d66c57a83b84139e34909e5ee81758f1ac8fda7`). `autoPatchelfHook` rewrites the ELF loader and library paths against the Nix closure, including `stdenv.cc.cc.lib`; installation checks the actual version. The initial musl artifact failed its launch check because it required `/lib/ld-musl-aarch64.so.1` and a musl C++ runtime. The glibc artifact avoids maintaining a second libc toolchain. This is a package-local fix; no global loader compatibility configuration is added.

Run `nix develop --option builders "" --option max-jobs 2 --option cores 2 --command bash -c 'rustc --version; bun --version; cargo test --workspace --locked'` inside the project NixOS server guest. Explicit empty builders prevent implicit remote dispatch. The development shell limits Cargo to four build jobs. Neither the host lab environment nor global tool defaults need modification.

The initial Nix package build and development shell passed on the NixOS guest; the NixOS service module, full runtime, OMP/Herdr installations, and portable release validation remain M1 work. The bootstrap image currently reports NixOS 26.11 with kernel 7.1.1; that observation is not final release validation. Record the final operating-system configuration separately from the pinned build environment.

Updating requires changing source/version hashes, regenerating flake.lock, running install checks and affected tests, and recording the result. Rollback uses the previous committed flake/lock; no global package uninstall is needed. Project build outputs and GC roots must remain explicitly scoped.
